# Правила работы кеш-агента

Эти правила обязательны: агент обязан сверять текущие значения из `settings.json`
и нижеприведённые дефолты перед каждым действием.

## Полный сброс кеша (flush)

Полный сброс стирает все ключи без исключения; это **рискованная** операция,
требующая явного подтверждения от оператора (`confirm=true`). Валидные режимы:
`scope=all | key | prefix`. Если `scope != "all"`, обязательно передать `target_keys`.

Рекомендации:
- перед full-flush сделать снапшот метрик hit-rate (см. `hit-cache-analysis`);
  после сброса промониторить load-spike в течение 5-10 минут;
- всегда логировать аудит-запись с идентификатором оператора.

## Погревание кеша (prewarm)

Погревание закладывает «горячие» ключи из source (`redis`, `api` или `file`) в кэш
с TTL, указанным явным параметром `ttl_seconds` либо дефолтным `cache.default_ttl_seconds`.
Батч-размер по умолчанию: `cache.prewarm_batch_size = 512`. Если список ключей пуст —
операция не изменяет состояние (no-op).

## Анализ hit-rate кеша

Окно анализа берётся из параметра `window_minutes` либо дефолта `cache.metric_window_minutes`.
Hit-rate вычисляется как `hits / (hits + misses) * 100`. При наличии `filter_prefix`
отбираются только ключи, начинающиеся с этого префикса.

## Инвалидация по паттерну

Глубина дерева (`depth`) ограничивает уровень вложенности; при `depth=1` удаляются
только ключи на корневом уровне заданного паттерна. Если `pattern` пуст — операция no-op.

## Очистка истёкших (cleanup-expired)

По умолчанию работает в dry-run режиме: посчитает объём, но ничего не удалит.
Для реального удаления нужно явно передать `dry_run=false`. Лимит записей за
проход — `cache.max_entries`. В реальном рантайме выводится число фактически
очищенных записей (`evicted_expired`).

## Топ ключей (top-keys-report)

В отчёт по умолчанию выдаются `cache.top_keys_limit` (20) горячих ключей. Формат — таблица
(`table`) или JSON (`top_keys`, список кортежей `{key, hits}`).
